## 三、地基：菜单与发现（Step 1–3）

### Step 1：菜单格式（索引 schema）✅
**要做什么**
- 设计 `plugins.json` 字段（**v0.1 精简版，11 个顶层字段**，见 `docs/design/menu-schema.md`）：
  - 身份：`id`（npm 包名优先）、`name`、`summary`
  - 来源与信任：`sources[]`（官方/topic/npm/精选/自荐）、`trustLayer`（官方✅/精选🟡/待验证⚠️）
  - 信号：`github`（星/标签/动工）、`npm`（版本/下载/官方盖章 dshDeclarations）、`score`
  - 时间：`firstSeen`、`updatedAt`
  - 安装：`install`（method + packageSpec）
- **决策 D6：不预埋未来字段**——categories / verifiedAt / riskReport / ratings 用到时靠升版（v0.2/v0.3）加回；
- 明确"生成端可换"：同一 schema 既能被本地脚本生成，也能被中央 Actions 生成。
**验收标准（已达成）**
- schema 能无损容纳"官方 monorepo 包"与"topic 仓库"两种来源 ✅；
- 中心化友好（含 firstSeen/updatedAt 时间戳）✅；
- 与 DSH 官方 publish.md / RFC #1629 方向不冲突（预留适配位）✅；
- 示例数据与产出数据通过 JSON Schema 校验（产出已用脚本自检；正式 ajv 校验待 Step 2 收尾补上）。
**产出**：`docs/design/menu-schema.md`、`docs/design/menu-schema-fields.md`、`data/schema/plugins.schema.json`、`data/examples/plugins.example.json`。

### Step 2：第一本电话簿（阶段 A）✅
**要做什么**
- `scripts/build-index.mjs`（无第三方依赖）：official-local（3 bundle）+ github-topic（分桶抓取 + **候选缓存**防烧配额）✅；
- 入选（D7 修订版）：依赖/盖章/官方，标签不算数 ✅；质量分 = 星星+活跃度+评分 加权（D9）✅；
- LLM 3-in-1（分类/安装/全面评估报告）✅ `scripts/lib/llm.mjs`（非 JSON 自动重试 + 结果缓存）；
- README/package.json：jsdelivr 优先 + GitHub API 兜底 ✅（raw 被墙）；
- 工具：合并 ✅ `scripts/merge-menu.mjs`；查询 ✅ `scripts/query-menu.mjs`（list/search/top/show/stats）；补缺报告 ✅ `scripts/fix-missing-reports.mjs`；审阅报告 ✅ `scripts/report-html.mjs` → `report.html`。
**实测结果（2026-08-16）**
- 候选 336 → 处理 108 → **入选 36**（+官方 3 = 菜单 **39 条**）；跳过 72（36 蹭标签 + 36 无 package.json）；
- 安装方式：npm 22 / git 14 / tarball 1 / **none 2**（none = 不可安装，不推荐）；
- LLM 成本：36 社区 ≈ **¥0.95**（约 2.6 分/个）；存疑清单 2 条；
- D7v2 正确挡掉全部高星蹭标签项目；评估报告含功能介绍/风险/装后要点/提醒，质量达标。
**验收标准**
- 官方 100% 覆盖 ✅；重跑一致（候选+LLM 缓存）✅；
- 误报 <5% —— 由"存疑清单 + 人工复查"承接，**待用户审阅 report.html 确认**。
**遗留**：deepseek-harness 本体被 LLM 标"other"（monorepo 误判，待定）；全历史 1800+ 需 GITHUB_TOKEN 或 Step 9 中央厨房。
**关联文档**：04 §二、§三、阶段 A；审阅入口 `report.html`。

### Step 3：增量发现（阶段 B）🔜
**要做什么**
- ✅ npm 通道验证通过（2026-08-16）：changes feed（replicate.npmjs.com）、搜索 API、jsdelivr npm 全通；
- ✅ `scripts/npm-scan.mjs`：两阶段（discover 体检 / llm 评估）+ 检查点断点续跑 + 并发（8/4）+ 实体合并（GitHub↔npm，含"官方仓库防误并"守卫）+ 增量基线 lastSeq；

## 四、店面：UI 与安装（Step 4–5）

### Step 4：只读市场 UI（DSH 插件）⬜
**要做什么**
- 做成 DSH 插件包：宿主半（cordis）+ 客户端半（自带 client bundle，声明 `dsh.client`）；
- 注册进 `settings.plugins.tab`（复用 locale/slot 体系）；
- 页面：浏览（分类）、搜索、详情（来源/评分/风险报告位）、排行（综合分）；
- **UX 设计蓝本（用户 2026-08-17 指定，report.html 已实现）**：① 分类（呈现层启发式，v0.2 进 schema）② 筛选（信任档/安装方式/来源）③ 排序（质量分/星星/下载/最新/名称）④ 检索（全字段全文）——正式前端沿用这套交互；
- 第一版**不含写操作**。
**验收标准**
- `dsh plugin add <market-pkg>` 装入 web profile 后，设置页出现市场 tab，UI 正常渲染；
- 空态、限流兜底可见。
**待核实（不阻塞）**：宿主侧服务暴露方式（首选 `ctx.webServer.register` 同源路由，绕开 api-proxy 白名单）。

### Step 5：一键安装（点击流程已设计，待用户拍板两个小点）⬜
**要做什么**
- **架构**：浏览器按钮（客户端半）→ 本地桥梁（宿主半，`ctx.webServer.register` 同源路由）→ 执行 `dsh plugin --profile <profile> add <packageSpec>`（复用官方对账逻辑）→ 回显结果；
- **四步点击流程（安全，不偷偷装）**：① 点按钮 → ② 确认框（插件名/来源/完整命令/风险提示）→ ③ 确认安装 → ④ 回显结果 + "重启 DSH 生效"提示；
- **边界处理**：pnpm 不在 PATH、`allowBuilds` 白名单（git 托管插件）、失败提示、profile 选择（**待拍板**：默认 web 可切换？）；
- 依赖 Step 4（按钮在详情页上），Step 4+5 一起做。
**验收标准**
- 装/卸/更新插件后 profile bundles 对账正确（重开 DSH 生效）；
- 每个边界场景有明确用户提示；确认框必须展示完整命令。
**关联文档**：01 §1.1、02 §决定性事实。

## 五、内容：风险报告、日报、信任分层（Step 6–8）

### Step 6：AI 风险报告（厨房生成 + 共享缓存）⬜
**要做什么**
- **厨房集中生成（D10 已定）**：Actions 调用厨房 LLM（API key 部署在 GitHub），产出安全评估报告写入共享缓存，所有用户读同一份；
- 输入：README + package.json（依赖、安装脚本）+ 目录结构扫一眼；
- 输出三段式 + 三档（😊 放心 / 🤔 留个心眼 / ⚠️ 别急着装）+ "装后要点"；固定标注"AI 生成的参考，非安全认证"；
- 同一调用顺带做**验货分类**（真插件/教程/清单/脚本），结果回流菜单；
- 兜底：用户本机模型可选（共享报告缺失时）。
**验收标准**
- 大多数插件落"放心"档（校准原则：不过度谨慎）；
- 共享缓存命中不重复调用模型；新插件当日/次日有报告。
**关联文档**：03 §一（已更新为厨房模式）。

### Step 7：每日日报（本地）⬜
**要做什么**
- cordis-plugin-timer 每日定时聚合：新插件 / 更新 / 本周趋势 / 编辑推荐；
- 日报渲染（可导出 Markdown）+ 历史快照存储（`history/`，趋势数据开始积累）。
**验收标准**
- 连续 3 天出报、数据一致、断网可重试。
**关联文档**：01 §1.4、02 §推荐架构。

### Step 8：信任分层落地 ⬜
**要做什么**
- 每件插件详情页展示：来源层徽章（官方✅/精选🟡/待验证⚠️）+ 来源列表 + 验证状态；
- 安装前风险提示页（综合信任层 + AI 报告 + 评分）。
**验收标准**
- 任何插件详情页可见来源层与验证状态；
- 安装确认流程必经风险提示。
**关联文档**：01 §2.3（官方 #587 安全讨论）、03 §一。

## 六、开张与闭环（Step 9–11）

### Step 9：厨房开张（阶段 C）⬜
**要做什么**
- 把生成流程搬进 GitHub Actions（免费）：每日产出 `plugins.json` + 日报 + 历史快照；
- 本地插件切为"优先读总菜单、直爬作兜底"；
- 仓库即菜单（可顺手起 GitHub Pages，见 Step 12）。
**验收标准**
- 消费端零改动（schema 不变，生成端可换的验证时刻）；
- 所有用户读到同一份菜单。
**关联文档**：02 §推荐架构、04 阶段 C。

### Step 10：反馈通道（阶段 D）⬜
**要做什么**
- 作者自荐（GitHub issue 表单起步）；
- 用户反馈通道（类型：装不上/用不了/可疑/失效，附 DSH 版本、插件版本、匿名身份）；
- AI 风险报告共享缓存（"买家评价"模式，一次生成万人读）。
**验收标准**
- 反馈能回流到菜单状态（标记/降级）；
- 自荐进候选池走同一套验证流程。
**关联文档**：04 阶段 D、05 §三。

### Step 11：评分机制（阶段 E）⬜
**要做什么**
- 写通道三选一（❓ 待定）：GitHub issue 批量合并 / Serverless 写接口 / 网站挂载；
- 规则：1–5 星 + 短评，每插件每匿名身份一票，展示分布直方图；
- 可选"装机验证"标记（用户同意上报已装清单）；
- 综合热度榜 = 星 + 下载 + 评分。
**验收标准**
- 同身份同插件不可重复投票；
- 热度榜与直觉一致。
**关联文档**：05 §四、§五。
